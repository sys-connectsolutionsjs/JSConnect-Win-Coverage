### Bug 1 — "UAC cancelado" sin que aparezca ningún UAC

- Al probar el botón **Mostrar** del panel "Credenciales del proxy" (agregado el
  2026-09-21), incluso corriendo `JSConnect-Win-Owner.exe` como Administrador,
  salía "No se concedió el permiso de administrador (aviso UAC cancelado)" sin
  que apareciera ningún diálogo de UAC real — señal de que el fallo ocurría
  antes de siquiera intentar elevar.
- Investigación en `generator/owner_app.py::_ejecutar_elevado()`: el script de
  PowerShell combinaba `-Verb RunAs` (exige `UseShellExecute=true` para poder
  elevar vía ShellExecute) con `-RedirectStandardOutput` (exige
  `UseShellExecute=false` para redirigir stdout con handles de pipe) en el mismo
  `Start-Process`. Esa combinación es inválida y PowerShell rechaza el
  parámetro-set **antes de lanzar ningún proceso**, cayendo directo al
  `catch { exit 2 }` del script — el mismo código que el flujo interpreta como
  "UAC cancelado". El mismo patrón `-Verb RunAs` sin `-RedirectStandardOutput`
  en `comando_reinicio()` (botón "Reiniciar servicio") funcionaba bien,
  confirmando que el problema era específicamente esa combinación.
- **Fix**: la ruta del archivo temporal de salida se pasa ahora como argumento
  posicional extra al proceso relanzado (`_comando_propio() + args_extra +
  [ruta_salida]`), y los subcomandos elevados (`_correr_subcomando_leer`,
  `_correr_subcomando_rotar`, dispatch en `main()`) escriben el JSON
  directamente en ese archivo con `Path(ruta_salida).write_text(...)` en vez de
  imprimirlo a stdout. El resto de `_ejecutar_elevado` (lectura del archivo,
  parseo JSON, manejo de `"error"`, borrado del temporal) no cambió.
- **Confirmaciones agregadas/ampliadas** (pedido del owner, previendo que el
  personal de la oficina abra la consola con doble clic normal en vez de
  "Ejecutar como administrador", así que el UAC real podría no esperarse o
  pasar desapercibido): **Mostrar** ahora pide confirmación propia
  ("Windows pedirá permiso de administrador... ¿Continuar?") antes de disparar
  el UAC — antes no pedía ninguna. **Rotar** ya tenía confirmación, pero se
  amplió para mencionar también que Windows pedirá permiso de administrador, y
  su mensaje final ahora indica dónde colocar el valor nuevo: para
  `proxy_token`, reconfigurar cada agente vía ⚙ Configuración → Configurar
  Proxy (o el script de keyring); para `admin_key`, aclara que solo lo usa esta
  consola y no hace falta distribuirlo.

### Bug 2 — `sc qc` en español rompe la detección del binPath

- Al reconstruir y volver a probar Mostrar (ya con el Bug 1 corregido), el UAC
  real apareció correctamente y se aceptó, pero salió un error distinto: "No se
  encontró config.yaml (servicio JSWinProxy no instalado o config.yaml
  ausente)" — **a pesar de que el servicio estaba instalado y corriendo
  (`sc query JSWinProxy` → RUNNING) y `config.yaml` existía** en
  `validator_app/proxy/config.yaml`.
- Causa: `validator_app/proxy/secretos.py::ruta_instalacion()` ejecuta
  `sc qc JSWinProxy` y busca la etiqueta `"BINARY_PATH_NAME"` en la salida para
  ubicar la carpeta real de instalación. Confirmado en esta PC que Windows en
  **español** traduce esa etiqueta a `NOMBRE_RUTA_BINARIO` — la condición nunca
  matcheaba, el bucle no encontraba nada, y caía al fallback de desarrollo
  (`_BASE_DIR_DESARROLLO`, la carpeta del propio módulo), que en el `.exe`
  empaquetado apunta al directorio temporal de extracción de PyInstaller (sin
  `config.yaml`), terminando en el error. El test existente
  (`test_ruta_instalacion_usa_binpath_del_servicio`) solo simulaba la salida en
  inglés, por lo que nunca se había detectado. Este bug afectaría a
  **cualquier PC de la oficina** (todas en español), no solo a esta.
- **Fix** (decisión del owner: detectar el idioma en vez de cambiar de comando
  de `sc qc` a `reg query`): `ruta_instalacion()` ahora prueba ambas etiquetas
  posibles (`_ETIQUETAS_BINARY_PATH = ("BINARY_PATH_NAME",
  "NOMBRE_RUTA_BINARIO")`), inglés primero como prioridad, español como segunda
  opción.
